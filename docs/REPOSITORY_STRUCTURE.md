# 狹間之森｜Repository 結構規劃

- 文件狀態：初版
- 版本：v0.1
- 原則：先建立可理解的骨架，隨作品需要再擴充

## 建議結構

```text
.
├── README.md
├── docs/
│   ├── PROJECT_INSTRUCTIONS.md
│   ├── CREATIVE_WORKFLOW.md
│   └── REPOSITORY_STRUCTURE.md
├── ideas/
│   └── README.md
├── world/
│   └── README.md
├── characters/
│   └── README.md
├── locations/
│   └── README.md
├── stories/
│   └── README.md
├── decisions/
│   └── DECISION_LOG.md
└── templates/
    └── IDEA_TEMPLATE.md
```

這是一份用途規劃，不代表每個資料夾都必須立即放入大量內容。若未來實際創作顯示分類不合用，可以調整。

## 資料夾用途

| 路徑 | 用途 |
|---|---|
| `docs/` | 協作規則、流程與本專案的方法論文件 |
| `ideas/` | 尚未整理、未確認或仍在探索的靈感素材 |
| `world/` | 世界規則、歷史、文化、超自然或其他系統性設定 |
| `characters/` | 角色檔案、人物弧線、關係與角色相關資料 |
| `locations/` | 場景、地點、空間特性與場景參考 |
| `stories/` | 正文、章節、故事大綱及作品版本 |
| `decisions/` | 影響後續創作的重要決策與變更紀錄 |
| `templates/` | 可重複使用的素材、角色或章節模板 |

## 命名原則

1. 優先使用清楚、穩定、容易搜尋的英文小寫檔名與連字號，例如 `forest-keeper.md`。
2. 文件內文可使用繁體中文。
3. 一個檔案盡量維護一個主要主題；當文件過長或多個主題開始頻繁分開更新時，再拆分。
4. 不要只為了分類而過早建立很多層子資料夾。
5. 章節編號應穩定，例如 `chapter-01.md`；若章節順序尚未確定，避免把暫定順序當成永久設定。
6. 重命名或移動檔案時，檢查 Markdown 連結與 Project 的「關聯文件」欄位。

## 正式性與文件位置

資料夾位置本身不代表設定已確認。正式性應在內容或管理卡片中明確標記。若某份文件只保存待確認方案，請在文件開頭清楚註明狀態。

## 目前不急著建立的內容

除非實際需求出現，暫時不必預先建立大量角色檔案、完整章節目錄、複雜的版本編號規則或自動化流程。先讓第一批素材跑過一次完整流程，再根據使用經驗調整。

# 狹間之森｜故事與創作方法

「狹間之森」是一個同時探索**故事本身**與**故事如何被創作、整理、修訂和延續**的長期創作計畫。

這個 Repository 不只保存故事成品，也記錄創作方法如何隨實際使用而演進。世界觀、角色、場景、情節、章節與寫作流程都可能逐步改變；重要的是讓創作保持開放，同時讓決策與修訂可以追溯。

## 專案的三個工作空間

- **ChatGPT 專案**：探索靈感、發展概念、共同寫作、編輯與檢查連續性。
- **GitHub Projects**：管理素材、任務、成熟度、正式性與創作進度。
- **本 Repository**：保存可追溯的正式文件、協作規則、故事素材模板，以及創作方法的演進紀錄。

三者不是自動同步的。對話中的討論不會自動成為正式設定；GitHub Projects 的欄位狀態也不會取代正式文件。需要依據既有設定創作時，應查閱相關文件；更新文件或卡片後，應明確確認實際完成的變更。

## 從哪裡開始

1. 閱讀 [GPT 專案指示](docs/PROJECT_INSTRUCTIONS.md)，了解共同創作的核心規則。
2. 閱讀 [創作協作流程](docs/CREATIVE_WORKFLOW.md)，了解素材從靈感走向正式文件的方式。
3. 查看 [Repository 結構規劃](docs/REPOSITORY_STRUCTURE.md)，了解不同資料夾的用途。
4. 建立新素材時，可複製 [靈感與素材模板](templates/IDEA_TEMPLATE.md)。
5. 重要設定決策請記錄於 `decisions/`，並在 GitHub Projects 的相關卡片上補上連結。

## 核心原則

- 尊重創作者的主導權；新想法先標記為「提案」，未經確認不視為正式設定。
- 保留多種可能，不急著把模糊的靈感收斂成唯一答案。
- 區分工作進度、設定正式性與文件保存狀態。
- 遇到設定衝突時先指出衝突與影響，不自行裁決。
- 讓刻意留白保持留白，不為每個謎團補上答案。
- 素材可以重複使用、改寫或延後採用，不因進入章節就失去其他用途。
- 創作流程應服務於故事，而不是限制故事。

## 文件與指示的維護

`docs/PROJECT_INSTRUCTIONS.md` 是 GPT 專案指示的版本管理來源。ChatGPT 專案設定中的指示文字屬於部署副本，GitHub 更新不會自動改寫 ChatGPT 設定；修改指示後，需手動同步，並在需要時確認實際貼入的版本。

創作方法也會隨使用而修訂。請優先記錄實際遇到的問題、修訂理由與預期影響，避免只因一次特殊情況就讓流程變得過度複雜。

## 目前階段

目前是專案起始階段：先建立文件架構與協作規則，再透過少量真實素材測試流程。資料夾可以隨作品發展逐步擴充，不需要一開始就建立完整而僵化的分類系統。
